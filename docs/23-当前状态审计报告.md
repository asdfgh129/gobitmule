## 四、性能审计

**结论：无回归；未夸大性能承诺。**

1. **回归基线**：`gates-strict` 的 `bench` 项 **PASS**，回环吞吐基线 **572.86 MB/s**。该数字是**同机回环回归基线，不是千兆链路 NFR 门禁**——本机回环噪声可达 ±3 倍，项目纪律明确禁止用它做性能声明或前后对比。文档均按此口径表述（`05` §5、`docs/README` v1.18 / v1.26、`CHANGELOG`）。
2. **既有真实性能结论**：NFR-PERF-01 以 ADR-0022 口径在双机百兆隔离段实测 1GiB / 91.367s = **11.21MB/s**、`met=true`（`20`）；`12` §5 单机四项已实测（内存增量 8.6MB / 启动 261ms / P99 45ms / 2h 长稳峰值 +12.5MB，`22`）。本次未重跑，保留原证据。
3. **热路径检查**：`TestChunkWriterDoesNotWriteMetadata` 守卫分片完成路径不产生元数据写；`metaBatcher` 的 group-commit 不把 500ms 固定延迟转嫁给单次 PATCH（单笔 2ms settle）。无证据表明存在每片事务或热路径同步等待钥匙串的问题；钥匙串 helper 调用按任务一次、不进分片循环（macOS 实测约 0.5s/次）。
4. **未做的性能项**（v1.0 时点，如实）：`12` §5 的 `ffmpeg exec` 开销与「分片哈希与转码不互饿」随 P2（`postproc.Transcode` 为 P2 占位，**无调用路径**）；移动端 BT 内存需真机；千兆 80MB/s 原口径由发起人 2026-11-17 指示略过（本环境无千兆链路），**不主动重跑**。
   —— **v1.1 补记**：前两项已随 P2 落地并实测 PASS（§九），当前仅剩移动端真机项。

### 9.2 实测结论（真实 ffmpeg 5.1.2 / 主机 A / 1 vCPU）

| 指标 | 实测 | 判定 |
|---|---|---|
| ffmpeg exec 开销 | 中位 **163.1ms** / P95 187.7ms / max 190.1ms（20 次） | **PASS**（目标 200–500ms） |

### 9.3 真实运行发现并修复的缺陷

输出名恒为 `<target>.transcode.part`，ffmpeg **无法从扩展名推断容器**，首次真实运行即报
`Unable to find a suitable output format`。修复为显式 `-f mp4|matroska|webm`，并新增
`TestTranscodeSelectsExplicitMuxer` 锁定「muxer 在输出前、输出仍是最后一个参数」。
该缺陷**单测与假 helper 无法发现**，是 P2 必须用真实 ffmpeg 验收的直接证据。
