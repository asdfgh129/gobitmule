# ADR-0022 NFR-PERF-01 性能基准口径修订（适配隔离段百兆实测环境）

- **状态**：Accepted（项目发起人 2026-11-16 指令裁决；代行五角色，非实名会签，依 `17` §1 P0 先例）
- **日期**：2026-11-16
- **决策者**：项目发起人（用户）于 2026-11-16 明确选择「发起人裁决修订 NFR-PERF-01 口径」
- **关联**：ADR-0021、`12` §5 性能基准、`12` §3.1.3/§3.1.4、`13` §7、`14` §11、`docs/README` §三、`18` §七/§十

## 背景

`12` §5 的 NFR-PERF-01 原目标为「HTTP 单任务吞吐（千兆内网）≥ 80MB/s」。2026-11-16
在隔离段真实双机环境复测时，发现物理链路存在无法绕过的能力上限：

| 环境项 | 实测值 | 来源 |
|---|---|---|
| 两台主机虚拟网卡标称速率 | 10000 Mb/s（10G） | `ethtool ens160` / `ens192` |
| 隔离段双向 TCP 吞吐（单流） | 94.1 Mb/s ≈ **11.8 MB/s** | iperf3 10s，`192.168.1.221 → 192.168.1.222` |
| 隔离段双向 TCP 吞吐（8 流并发） | 94.1 Mb/s ≈ **11.8 MB/s** | iperf3 `-P 8`，与单流一致 |
| 判定 | **物理链路硬限速 100 Mbps**，非 TCP 单流窗口问题 | 单/多流一致 |

两台主机均为 VMware 虚拟机（Ubuntu Server 23.04，x86_64），经 `192.168.1.0/24`
隔离段互通，延迟 0.36ms。8 流与单流吞吐完全相同，排除 TCP 窗口/拥塞算法因素，
确认瓶颈在虚拟化网络或上游物理链路的 100Mbps 限速——**代码与配置层均无解**。

按原口径，NFR-PERF-01 在此环境必然 FAIL（11.8 vs 80 MB/s，差约 7 倍），
即使 L4 互操作 14/14 PASS，序 6 也无法关闭。原目标的验收强度与实际可达链路
严重脱节，继续以原口径作为发布门禁将产生「形式不可满足」的锁死（与 ADR-0021
处置前的 BT-02/11 冲突同类）。

## 决策

**以项目发起人身份，将 NFR-PERF-01 的验收口径修订为「在实验室实际可用链路上实测并如实记录，门槛取可用链路理论上限的 80%」。**

| 项 | 修订前（时点值，保留不改） | 修订后（本 ADR 生效口径） |
|---|---|---|
| 目标表述 | HTTP 单任务吞吐（千兆内网）≥ 80MB/s | HTTP 单任务吞吐（隔离段实际链路）≥ 可用链路理论上限 × 80% |
| 当前实验室门槛 | 80MB/s（要求 1GiB 链路） | 100Mbps 链路上 **≥ 10MB/s**（=12.5MB/s × 80%，取整留余量） |
| 达标判定 | 单一固定数值 | 随实验室实测链路速率动态确定，须附 iperf3 原始证据 |
| 证据要求 | `dist/perf.json` 回环参考 | 双机 iperf3（单流+8流）+ 被测 HTTP 下载实测，两者都记录 |

配套约束（不可省略）：

1. **如实标注链路速率**：任何引用本门槛的证据必须同时给出 iperf3 实测链路速率
   （当前 94.1 Mbps），并明确标注「非千兆内网」。
2. **不得冒充千兆达标**：`12` §5 原「千兆内网 ≥ 80MB/s」表述作为历史时点值保留，
   不得改写为已达标；对外文案（`16`）仍不得写「千兆内网达标」。
3. **验证强度下降须显式声明**：本修订承认 HTTP 吞吐验证强度低于原千兆口径，
   风险由发起人在本 ADR 中承担；评审组后续复签时应复核该风险是否被接受。
4. **门槛随环境升级自动失效**：若实验室链路升级至真千兆，本 ADR 的 10MB/s
   门槛立即失效，恢复 `12` §5 原 80MB/s 口径，须重新实测。

## 备选方案（未采纳）

- **保持原 80MB/s 门槛，序 6 因性能保持开放**：诚实但形式锁死，发起人未采纳。
- **更换真千兆物理机/网卡直通**：需要新硬件，当前环境不具备；若后续提供，按约束 4 恢复原门槛。

## 后果

- **正面**：NFR-PERF-01 在现有实验室可真实判定（当前门槛 10MB/s，实测 11.8MB/s
  的链路能力足以承载），序 6 不再因「形式不可满足的性能门槛」锁死。
- **负面 / 风险**：吞吐验证强度从千兆降至百兆级，无法证明真千兆链路下的行为；
  该风险由本 ADR 显式记录，须在评审复签时复核。
- **合规**：本 ADR 是发起人口径裁决，非评审组签署；与 ADR-0021 R5 同样按
  `17` §1 先例代行五角色、非实名会签，不冒充实名会签。
