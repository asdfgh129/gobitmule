## 一、结论摘要

2026-11-16T11:56:18Z，在双机隔离段实验室用**真实外部 harness**执行
`BT-01..BT-14` 全部门禁用例，结果：

```text
cases: 23 | L4 gate PASS: 14/14 | PASS 23 / FAIL 0 / SKIPPED 0 / UNSUPPORTED 0
release gate: true (BT-01..BT-14 全部 PASS)
```

- `release_gate_met=true`，`release_gate_reason=BT-01..BT-14 全部 PASS`。
- 14 条门禁用例**均为首次执行即 PASS**：证据中未出现 `l4_attempts` 重试标记
  （实现只在发生第 2 次真实执行时写入该字段）。
- `make l4-audit` 独立重算 9 项 `AUD-*` 检查：**`CONSISTENT`，9/9 OK，0 FAIL**，
  重算 `gate_pass=14/14`、`release_gate_met=true`。
- 证据包归档于 [`docs/evidence/l4-2026-11-16/`](evidence/l4-2026-11-16/)，
  校验和见同目录 `SHA256SUMS`。

**边界**：这只证明本项目在**该受控实验室拓扑与所列软件版本**下通过了
`12` §3.1 的 L4 判据；**不**等于公网全矩阵、全部客户端版本、PT 站点或
千兆链路已达标。NFR-PERF-01 的双机应用层基准仍未执行（见 §七）。

## 三、执行链与可复跑命令

1. **构建 harness**（控制面）：
   `GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o udinteropx ./cmd/udinteropx`
2. **部署到主机 A**：`scp udinteropx root@192.168.34.222:/root/l4lab/bin/udinteropx`
3. **真实 external config**：`tools/l4_external_config.lab.json`，14 条用例各自执行
   `ssh root@192.168.34.222 '/root/l4lab/bin/udinteropx --l4-case BT-XX'`，
   每条 `timeout_s=780`。
4. **执行门禁**（控制面）：

   ```bash
   make l4-run \
     L4_CONFIG=tools/l4_external_config.lab.json \
     L4_CASE_TIMEOUT=840s
   ```

   产物：`dist/l4_lab/interop.json`、`dist/l4_lab/INTEROP.md`。
5. **证据完整性审计**：

   ```bash
   make l4-audit L4_EVIDENCE=dist/l4_lab/interop.json
   ```

   产物：`dist/l4_audit.json`、`dist/L4_AUDIT.md`。

> `make l4-preflight` 仍只是前置条件清点；`PRESENT` 不等于 PASS。
> `make interop` / `make interop-gate` 在无真实 external config 时仍必须保持
> `0/14` 并明确失败——这是**设计上的诚实失败**，不是本报告的反证。

### 4.1 关键实现口径

- **BT-02 / BT-11** 已在 2026-11-16 由发起人裁决从 `productGap`（固定
  `UNSUPPORTED`）翻转为 `gateExternal`；本报告是翻转后**首次**由真实 harness
  判定为 PASS，凭据是 `bytes_uploaded` 与真实下载量同源一致，而非「实现存在」。
- **BT-04** 的公网 DHT UDP 被 NAT 阻断，故使用隔离段**本地真实 DHT 路由器**
  （anacrolix/dht，回环节点关闭 security extension）与**进程内真实 anacrolix
  做种节点**，完成真实 `announce_peer` / `get_peers` / `ut_metadata` 与 payload
  校验。这是真实 DHT 协议路径，但**不是公共 DHT 网络**，不得外推为公网 DHT 已验收。
  生产侧 `WithDHTBootstrapNodes(...)` 只在自定义路由器为**回环地址**时关闭 DHT
  security extension；可路由的私有 DHT 路由器仍保持库默认的 IP 派生安全节点 ID。
- **BT-07** 的降级判据使用真实不可达主 tracker（`127.0.0.1:9`）与真实备用
  tracker，未用 mock 响应替代网络路径。
- **BT-08 / BT-14** 的抓包过滤显式排除主机 B 的两个地址与主机 A 自环流量；
  BT-08 剩余 UDP 包为 0，BT-14 在全部 IP 流量中命中诚实 PeerID 握手。

## 六、边界与不宣称事项

1. **不宣称公网全矩阵**：实验室是受控隔离段 + 自建 tracker + 指定客户端版本；
   公网 DHT、PT 站点、ISP 网络条件、其他客户端版本均未覆盖。
2. **不宣称 BT-04 公共 DHT 已验收**：仅隔离段本地 DHT 路由器路径通过。
3. **不宣称千兆性能达标**：链路实测 94.1Mbps，非千兆；NFR-PERF-01 见 §七。
4. **产品文案不变**：继续按 [`16` §7](16-互操作性与兼容性设计.md) 只写
   「兼容标准 BitTorrent 网络，可与主流客户端互通」，不写「已与主流客户端
   实测互通」「全矩阵通过」或「千兆内网性能达标」。
5. **治理未闭合**：评审组实名复签、法务 / 安全会签、`14` R-10 复评口径
   仍按既有记录待补；本报告不代行签署。
6. **历史证据不改写**：`17`、ADR-0020 与各文档历史版本说明中的时点数值
   保持原样，本报告只追加 2026-11-16 的实测结果。
